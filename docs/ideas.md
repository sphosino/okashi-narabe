# アイデア帳

まだ決まっていないこと・妄想をためておく場所。決めたこと・試した結果は別のファイル（例：[手持ちの数と時間切れ](hand-size.md)）に書く。

## 目指すもの

- AIで作るのが安くなるほど、ゲーム自体はあふれる。残る価値は**人と人の間に生まれるもの**（駆け引き、また遊びたい相手、続いていく関係）。
- 3人ゲームは、それを小さく試せる入口。おかしならべはその第一弾の実験。
- 確かめたいのは、
  1. 見た人が「友達と遊んだら楽しそう」と思うか
  2. 3人で遊んだら、もう1回やりたくなるか
  3. 「またこのゲーム」ではなく「**またあの人と**」遊びたくなるか

## お金の形：雀魂（じゃんたま）型

| 雀魂 | おかしならべ |
|---|---|
| 段位戦 | 3人の段位戦（ガチ）。1位だけが勝ち、2位・3位は点で順位 |
| 友人戦 | 3人で部屋を作って遊ぶ |
| CPU戦 | 今のCPU（やさしい〜つよい） |
| 雀士の着せかえ・ガチャ | **お菓子そのものがキャラ**。盤の上でずっと見える |
| リーチ・和了の演出 | 恋モードの「ドキッ」、恋ボーナスの「恋の力 +1」 |
| 卓・牌の背 | 盤、手持ちのお皿 |

- **強さはお金で買えない**（見た目と演出だけ）。ここは崩さない。
- 着せかえても、3人のお菓子は席の色の枠などで見分けられるようにする。

## 対戦のしかた

- **3人そろうのがいちばんの壁**。2人対戦より、同時に遊ぶ人をそろえるのがずっと難しい。
- 順番に1手ずつのゲームなので、**同時にいなくても遊べる対戦**にできる。それぞれ空いた時間に1手打ち、「あなたの番です」と通知が来る。
  - 3人の都合を合わせなくていい
  - 同じ3人の試合が何日も続くので、自然と「いつものメンツ」になる
- 人が足りない席はCPUで埋める。
- 最初に試すなら：**リンクを送ると3人の部屋に入れる友人戦**。
- **のんびり対局（持ち時間なし、空いた時間に1手ずつ）は、今は入れない**（2026-10-16）。調べると、使われているのは「あなたの番です」の通知があって、相手が知り合いのとき（Words With Friends は通知が入って伸び、遊び始めた人の6割が友達の誘い。OGS の囲碁は通信対局が多い）。一覧から知らない人と遊ぶ今の形では成り立たないので、「3人組」と通知を作るときにセットで考える。
- 友人戦ができたら **Discord のアクティビティ**に出す案。友達がもう通話で集まっている場所なので、3人そろう壁がほぼなくなる。リンクで部屋に入る形で作っておけば、そのまま持っていきやすい。

## 段位・ランキング（人が増えてから）

- 2026-10-16 に考えた形：**「みんなと遊ぶ」で人が2人以上いる試合だけ**を数える（勝ち負けはサーバーが判定するので、ごまかせない。CPU 戦は画面の中だけで動くので数えない）
- 順位でポイント（例：1位 +30・2位 +5・3位 −15）。たまると 初心者 → 1級 → 初段 → 二段…。**段位を名前カードに出す**（「この人、初段なんだ」がやりとりのきっかけになる）
- ランキングのページ（上位30人）をトップページから
- 記録はブラウザの秘密の番号（pid）とひもづけてサーバーに。ほかの端末へは「引き継ぎコード」をあとで
- 遊ぶ人が少ないうちは、ランキングがさびしく見えるので、人が増えてから作る
- 軽い代わり：**今日のチャレンジ**（全員が同じ盤で CPU と戦い、何手で勝てたかを比べる。ごまかせるが、ひとりでも遊べる）

## 3人組（3人フレンド）

- ふつうのフレンドは1対1。おかしならべでは**3人全員が同意したら3人組**が成立する。麻雀の「いつものメンツ」に近い。
- 成立しやすくする流れ：
  1. 試合後に「この3人でもう一回」を全員が押したら再戦
  2. 再戦が2〜3回続いたら「チームにする？」と聞く
- 誰が断ったかは、ほかの人に知らせない。
- 1人が抜けても残り2人の関係は残り、新しい3人目を迎えられる。
- 3人組の対戦記録を残す。

## やりとり：チャットなし、スタンプだけ

- 荒らしや迷惑行為への対応がほぼいらない（運用の手間が減る）。
- 話題がなくても、雑談が得意でなくても、**一緒に遊ぶだけでつながれる場**になる。

## コマをお菓子ではなく本人のアバターにする？

- 良い点
  - 盤のコマが「その人そのもの」になり、**誰と遊んだかが記憶に残る**（「あのウサギの人、入れかえがうまかった」）。「またあの人と」に合う
  - 3人のコマを見分けやすい（お菓子の着せかえで心配だった点がなくなる）
  - アバターの着せかえ（服・髪型・表情・ポーズ）は、それだけで大きな市場
- 気をつけたい点
  - **「食べる」話が合わなくなる**。揃ったときの意味を考え直す（例：4人そろったらハイタッチして帰っていく）
  - **恋モードの意味が変わる**。知らない人同士だと「入れかえたら相手のアバターが自分に一目ぼれ」は、面白い人もいれば気まずい人もいそう。友達同士ならネタとして盛り上がりそう
- 間を取る案
  - **コマはお菓子のまま、揃ったお菓子を食べに来るのが本人のアバター**（下のペットの役をアバターが担う）
  - **お菓子にアバターの飾りを付ける**（お菓子の上にその人の帽子や髪型が乗っている）
- どれにするかは、知らない人と遊ぶ場面と、友達同士の場面のどちらを中心にするかで変わる

## ペット

- **見た目だけのペット**：揃ったお菓子を食べに来るのが自分のペットになる。勝ち負けには影響しない。
  - 犬は走ってきてパクッ、猫は前足でちょいちょい、ハムスターは頬袋に詰めて帰る
  - 恋ボーナスのときは、ペットもハートの目になる
- **3人組で1匹のペットを一緒に育てる**：「あの子の世話があるから、またこの3人で集まる」という理由になる。

## わいわいモード（ガチの段位戦とは別）

**2026-10-16：最初の4つ（キューピッドの矢・いぬ・失恋の雨・はと）を「わいわい」ルールとして作った**（README の「わいわい」）。キューピッドの矢は「好きな相手のお菓子」ではなく「自分のお菓子」を恋モードにする形にした（相手を恋モードにすると、相手に恋ボーナスのチャンスをあげてしまうので）。残りは下の案から。

全員が同じ条件で、変なアイテムを使える。友達同士で笑うためのモード。

**ペット系**
- **犬**：相手2人のどちらかのお菓子を1つ、くわえて持っていく
- **猫**：盤のお菓子を1つ、となりのマスへ勝手に転がす（誰が得するかは運）
- **ハト**：自分の手持ちにお菓子を1個運んでくる

**恋モード系**
- **キューピッドの矢**：好きな相手のお菓子を1つ恋モードにする
- **失恋の雨**：盤の恋モードのお菓子が、全員ぶん目をさます
- **ラブレター**：次の自分の番だけ、ふつうと恋モードの間でも入れかえられる

**3人ならでは**
- **こっそり買収**：次の1手だけ、2人のうち1人の手を自分が選べる
- **おすそわけ**：自分が揃えたら、ビリの人にも1点入る

**決まりごと（案）**
- アイテムは全員が同じ条件で手に入れる（盤に落ちてくる、何手かごとに配られる など）。お金では買えない
- 1試合に使えるのは1〜2回まで
- 何が起きたか一目で分かる演出を必ず付ける
- 作るときは `rules.js` に足して、CPU同士で回して「運がどれくらい勝敗を左右するか」を確かめる

- ただし見た目はまだ変わるので、本格的な広告素材づくりは後回し。

## だるまさんがころんだ（2026-10-17）

試作：`Desktop/idea_projects/daruma-kids/index.html`（子ども役で遊ぶ。けんじさんの感想「やば、たのしいじゃん」）。元の `idea_projects/daruma`（だるま役 vs AIの子ども）とは別に作った。

- **今の形**：子ども役は押しっぱなしで走る（離すと少しすべる）。だるまは言い方を毎回変え、**強気度**（低〜激。光の色・大きさ・脈で見える）と**気力**（見送るとたまり、振り向くと使う。足りないと振り向けない）で、振り向くか見送るかを決める。タッチしたら子どもの勝ち
- **逃げる場面は入れない**：伝統の遊びでは、タッチしたあと全員が逃げ、鬼の「ストップ」と数歩でタッチされた子が次の鬼。ゲームにすると走る速さと歩幅で結果がほぼ決まってしまうので、入れない
- **ひと休み**：振り向いて見終わったあと、子どもは動けない（水を飲む時間）。長さはだるまが決める（試作のCPUは1〜3.5秒）。言い始める0.8秒前に「すぅ…」と合図が出て、子どもにも伝わる。次の強気度はここで見える。**ひと休み中にサプリを飲む**（足が速くなる・すべりにくくなる・下がる量が減る など）案もあり
- **捕まった子のアイテム応援（案）**：捕まった子がただ見ているだけにならないように、アイテムで仲間を応援できる（足が速くなる、すべりにくくなる など）
- **みんなで遊ぶ版**：だるま1人（人）＋子ども（人とCPU）。部屋のしくみはおかしならべのサーバーを使い回す。通信の遅れで「止まったのにアウト」にならない工夫がいる
- **だるまの勝ち条件**：元の daruma は「言っている間だけ進む時計（40秒）」で、休憩・振り向きは時計に入らない。テンポを固定して元のシミュレーターで回すと（2026-10-17、各1000試合）、人間の読みのだるまの勝率はテンポ50〜60で山（85%）、速すぎると気力が尽きて振り向けず6%。一度も振り向かないは全テンポで3〜11%。速く言うほど得、にはなっていない。だるまが少し強すぎるかもしれない（人数・時間で調整）
- **伝統のだるまさんがころんだ**（捕まると手をつなぐ・「切った！」・逃げる・次の鬼）は、「公園」のプロジェクトで作りたい

### 見送ったとき（2026-10-18 に決めた）

- 振り向かずに見送ったら、**止まらない**。最後の「だ」が次の「だ」を兼ねて「…ころん だ るまさんが…」とそのまま言い続ける。子どもは走り続けられる（だるまは時間を稼げるが、子どもに近づかれる）
- 強気度は、言っている間いつでも次のぶんを予約でき、見送りの「だ」で変わる。ひと休み中はすぐ変わる。予約にしたのは、決まった秒数の窓だと見送りの瞬間が忙しいため（前は1秒の窓だった）。何も押さなければ前のまま
- 勝ち条件が「言っている間の秒数」なら、見送りが続いても子どもにとって理不尽ではない
- だるまが忙しすぎないかは、人がだるまをやってみないと分からない

### 振り向いたときの見せ方と、下がる量（2026-10-18）

- 今は「だ」で振り向いた0.1秒後にパッと下がる。けんじさん「何が起きてるかわからんのにノックバックされたらストレス」。止まりきれずに負けることが多く、遊んだ感じも強さの測り方もゆがむ
- 直す案（まだ作っていない）：振り向くのが見える（0.2秒）→ じっと見る（1.2秒くらい。この間も体は動く。猶予0.3秒くらいのあとも動いていたら見つかる）→ 見つかった子に「！」とすべった跡、自分なら「あと0.2秒早く離せば止まれた」→ ギューっと押し戻される（0.6秒）→ ひと休み
- 下がる量（今は40）はちょっと大きすぎるかも
- アイデア：だるまの種類によって、下がる量（押し戻す力）が変わってもいい
- 操作が「押す＝加速、離す＝ブレーキ」だけなので、ゆるめに走るには押したり離したりするしかない。走り方で読み合うなら、速さを選べる操作（引く量で速さ、など）も考える（2026-10-18、けんじさん「加速か減速しかないのはちょっとあれ」）

### 体力と番勝負（2026-10-19）

- けんじさん「体力が尽きることがなさすぎじゃね？ でも現実でも1回のプレイで疲れ切ることはない。何番勝負とかやってたら疲れる」
- シミュレーター（CPU のだるま相手・時計46秒・300局）で、1回のプレイで「ぜぇ」になったのは CPU の子 13%・人っぽい子 4%。いちばん減ったときでも体力は平均して半分くらい残る（言い終わり前に止まる・ひと休みで戻るため）
- 1回のプレイの中の体力は今のままでいい（ずっと全力で走り続けたときだけ効く、軽い歯止め）
- 案：**番勝負で体力を次の回に持ち越す**。回を重ねるほど疲れて、最後のほうは足が出なくなる（本物の遊びと同じ）。「この回は温存して次で勝負」のような回をまたいだ作戦が生まれる。だるま役の回は走らないので体力が戻り、役を交代しながら遊ぶ形と相性がいい
- 決めること：役の交代のしかた、途中から入った人の体力、何回勝負にするか、回の間にどれだけ戻るか
- 時期：みんなで遊ぶ版（友だちと何回も続けて遊ぶ）を作るときに一緒に考える。CPU 相手の1回ずつの版では、ありがたみが少ない

## 人狼サイト（2026-10-20）

けんじさん「ずっとやりたいと思っていた。擦りつくされてはいるけど」。チャットで話し合う、人狼オンラインのような形。**知らない人どうしで遊ぶ**（友だちどうしの部屋ではなく）。リアルタイム（話し合いに制限時間、チャットとスタンプ）

- また遊ぼの「ゲームで、もっと、つながる。」にいちばん真っすぐ合う。会話そのものが遊び
- いちばんの壁は**人が集まるか**。ふつうの人狼は1部屋7〜15人いる。広告もいる（けんじさん「これこそ広告打たないとだしなぁ」）
- 続くかはゲームの出来より、遊ぶ人の集まり（コミュニティ）ができるかで決まる

案
1. **小さな村から**：5人くらい（人狼1・占い師1・村人3）、1回10分くらい。少ない人数でも村が立つ
2. **時間を決めて集める**：「毎晩21時に村が開く」のように決めて X で知らせる。いつでも少しずつより、決まった時間に集まるほうが少ない人数で回る
3. **足りない席は AI のプレイヤーで埋める**：4人しか来なくても始められる。「AIにだまされた／見破った」は話題にもなる。AI を動かすお金がかかるので、1回の村でいくらかかるかを作る前に見積もる
4. **荒らし対策を最初から**：通報とブロック、ひどい言葉の自動チェック、連投の制限、利用規約。名前だけで遊べるようにしつつ、悪い人をはじける
5. 部屋のしくみは okashi-narabe のサーバー（Cloudflare Workers ＋ Durable Objects）を使い回せる

進め方：いきなり大きく作らない。小さく作って、X や知り合いのつながりで、決まった時間に10人くらい集まるかを試すところから

メモ：だるまさんがころんだを作って分かったのは、リアルタイムの要素（手ざわり・何が起きたか見せる・通信の遅れ・CPU の考え方・1秒で変わるバランス）がむずかしさの大もとだということ。人狼は話し合いがリアルタイムでも、判定は投票や夜の行動の順番に決まるので、だるまほど手ざわりで悩まないはず
